# iterate MCP 核心流程详解

> 本文档详细解释 iterate 如何通过 MCP 协议与 IDE 通信

---

## 一、什么是 MCP？

**MCP (Model Context Protocol)** 是 Anthropic 提出的协议，让 AI 助手能够调用外部工具。

简单理解：
- **MCP 是一种"语言"**：AI 和工具之间的通信协议
- **MCP Server 是"翻译官"**：把 AI 的请求翻译成具体操作
- **iterate 是"执行者"**：显示弹窗，收集用户输入

---

## 二、核心流程（6 步）

### 流程概览

```
步骤 1: IDE 启动 MCP Server
步骤 2: AI 调用 zhi 工具
步骤 3: MCP Server 写入请求文件
步骤 4: 启动 iterate 子进程
步骤 5: 用户在弹窗中交互
步骤 6: 响应返回给 AI
```

---

### 步骤 1: IDE 启动 MCP Server

**触发时机**: 打开 Windsurf/Cursor 时自动启动

**发生了什么**:
1. IDE 读取配置文件 `~/.codeium/windsurf/mcp_config.json`
2. 配置指定了 MCP Server 的路径：`/Applications/iterate.app/Contents/MacOS/mcp-server`
3. IDE 启动这个进程，建立 stdio 通道

**配置文件示例**:
```json
{
  "mcpServers": {
    "iterate": {
      "command": "/Applications/iterate.app/Contents/MacOS/mcp-server",
      "args": []
    }
  }
}
```

**通信方式**: stdio（标准输入输出）
- IDE 写入 stdin → MCP Server 读取
- MCP Server 写入 stdout → IDE 读取

---

### 步骤 2: AI 调用 zhi 工具

**触发时机**: AI 需要和用户交互时

**发生了什么**:
1. AI 决定调用 `zhi` 工具（或 `mcp0_call_zhi`）
2. AI 构造请求参数：
   - `message`: 要显示给用户的消息
   - `predefined_options`: 预定义选项（可选）
   - `project_path`: 当前项目路径（可选）
3. 请求通过 stdio 发送给 MCP Server

**请求示例**:
```json
{
  "method": "tools/call",
  "params": {
    "name": "zhi",
    "arguments": {
      "message": "## 任务完成\n\n请确认是否继续",
      "predefined_options": ["继续", "取消"],
      "project_path": "/Users/example/cunzhi"
    }
  }
}
```

---

### 步骤 3: MCP Server 写入请求文件

**触发时机**: MCP Server 收到 zhi 工具调用

**发生了什么**:
1. MCP Server 解析请求参数
2. 生成唯一的 request_id（UUID）
3. 构造 PopupRequest 对象
4. 写入临时文件 `/tmp/mcp_request_{uuid}.json`

**临时文件内容**:
```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "message": "## 任务完成\n\n请确认是否继续",
  "predefined_options": ["继续", "取消"],
  "is_markdown": true,
  "project_path": "/Users/example/cunzhi"
}
```

**为什么用文件**:
- 避免命令行参数过长
- 支持复杂的 JSON 数据
- 便于调试

---

### 步骤 4: 启动 iterate 子进程

**触发时机**: 请求文件写入完成后

**发生了什么**:
1. MCP Server 执行命令：
   ```bash
   iterate --mcp-request /tmp/mcp_request_{uuid}.json
   ```
2. iterate 进程启动
3. iterate 读取请求文件
4. iterate 显示 GUI 弹窗

**关键代码** (`popup.rs`):
```rust
let output = Command::new("iterate")
    .arg("--mcp-request")
    .arg(temp_file_path)
    .output()?;
```

**注意**: MCP Server 会**同步等待**子进程完成

---

### 步骤 5: 用户在弹窗中交互

**触发时机**: iterate 弹窗显示后

**用户可以做什么**:
1. 查看 AI 发送的消息（支持 Markdown 渲染）
2. 点击预定义选项
3. 输入自由文本
4. 上传图片
5. 点击发送

**弹窗界面组成**:
- 顶部：项目路径显示
- 中间：消息内容区域
- 底部：输入框 + 选项按钮 + 发送按钮

---

### 步骤 6: 响应返回给 AI

**触发时机**: 用户点击发送

**发生了什么**:
1. iterate 前端收集用户输入
2. 构造响应 JSON
3. 通过 stdout 输出响应
4. iterate 进程退出
5. MCP Server 读取 stdout
6. MCP Server 解析响应
7. 通过 stdio 返回给 IDE
8. AI 收到用户响应

**响应示例**:
```json
{
  "user_input": "好的，继续执行",
  "selected_options": ["继续"],
  "images": [],
  "files": [],
  "keep_going": true
}
```

**AI 收到的格式化响应**:
```
用户输入: 好的，继续执行
选中的选项: 继续
附加图片: (无)
继续对话: true
```

## 四、关键概念总结

| 概念 | 说明 |
|------|------|
| **MCP** | Model Context Protocol，AI 与工具的通信协议 |
| **stdio** | 标准输入输出，IDE 与 MCP Server 的通信方式 |
| **MCP Server** | 协议翻译器，把 AI 请求转换为具体操作 |
| **zhi 工具** | iterate 提供的交互工具，用于显示弹窗 |
| **request_id** | 每次请求的唯一标识（UUID） |
| **临时文件** | 用于传递复杂请求数据 |
| **子进程** | MCP Server 启动 iterate 的方式 |

---

## 五、为什么这样设计？

### 1. 为什么用 stdio 而不是 HTTP？
- stdio 是最简单的进程间通信方式
- 不需要端口管理
- IDE 可以直接管理进程生命周期

### 2. 为什么用子进程而不是常驻服务？
- 每次请求独立进程，天然隔离
- 不需要复杂的会话管理
- 简单可靠

### 3. 为什么用临时文件传递请求？
- 命令行参数有长度限制
- JSON 数据可能很复杂
- 便于调试和日志记录
