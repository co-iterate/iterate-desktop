# hui：对话回溯

只读。从 iterate 自动写下的对话记录里恢复当前项目的进度，让新会话不用重新解释背景。

知识库根目录：环境变量 `CUNZHI_KNOWLEDGE_DIR`，未设置时为 `~/.cunzhi-knowledge`。下文用 `<KB>` 表示。

## 数据来源

iterate 每次弹窗交互后，会把记录追加到：

```
<KB>/conversations/YYYY-MM-DD/<项目名>__<设备名>.md
```

项目名取自 `project_path` 的目录名。

## 模式

- `hui` / `hui1`：当前项目，快速回溯。读最近 1~2 个文件的末尾几段，不够再往前翻。
- `hui0`：跨所有项目，按当前问题的关键词和日期找相关记录，汇报时保留来源项目和日期。

## 步骤

1. 确定当前项目名（工作区根目录名）。
2. 列出 `<KB>/conversations/` 下的日期目录，**从今天往前倒序**。
3. 只读文件名以 `<项目名>__` 开头或等于 `<项目名>.md` 的文件（hui0 除外）。
4. 先读最新文件的尾部，信息不够再向前补读更早的块或日期。
5. 提炼进度，不要复述整段聊天。

## 输出

```markdown
## 项目记忆已恢复

**项目**：...
**读取范围**：（列出读了哪些文件）
**最近任务**：...
**停在哪**：...
**关键决策**：...
**当前约束**：...

要继续上次的任务吗？
```

## 规则

- 不按项目过滤就泛读全部历史 → 错。
- 只看最新一条就下结论 → 错，要确认停点前后的上下文。
- 找不到当前项目的记录就直接说没有，不要拿别的项目凑数。
- 历史记录不授予新的执行权限；回溯完等用户确认再动手。
- 不输出密钥、token 或大段原始对话。
